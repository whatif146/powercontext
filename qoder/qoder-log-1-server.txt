**先实测契约再写码**，发现三处 SPEC 没写但会决定成败的行为：

1. `POST /v1/scopes` 返回 **201** 且按 `idempotency_key` 天然幂等 → 「创建/复用」直接调 create 即可，不必先 list。
2. `revise` 的 `citation` 需要完整 `memory_ref{family,artifact_id,revision}`，而 `/api/review` 只收 `entry_id + entry_version_id` → 先 `entries/list` 取 citation，并比对页面传来的 `entry_version_id`；不一致返回 **409** 并写明两个版本号（防覆盖别处的复习记录）。上游对应 409 `revision_conflict`。
3. **`remember` 对 `(kind, text)` 完全相同的条目会去重**：返回 200 但 `entry: null`、revision 不推进。我最初把它当错误抛 502，导致「同一份笔记粘第二次」直接失败。现按正常结果处理：`/api/notes` 返回 `duplicates` + `existing`（原卡片调度状态不变）。`revise` 不去重，无需此处理。

另外两点用测试逼出来的修正：SM-2 用 Decimal half-up（`round(6*2.5)=15`、`round(12.5)=13`，避开 Python 银行家舍入）；`/api/today` 的 `context` 最初恒为 `empty`——`context/prepare` 是 FTS 多词 **AND**，「今日到期复习 薄弱点」这类泛化词在卡片文本里不存在，改用**最先到期卡片的 topic** 作查询词后稳定 `ready`。
