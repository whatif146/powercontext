# 会议纪要 → 行动项清单

## 何时使用

用户给出一段会议记录/聊天记录/语音转写，希望得到「谁、在什么时候、要交付什么」。典型请求：

- 「把这段周会记录整理成待办」
- 「帮我从聊天记录里拆出行动项，标一下谁负责」
- 「会后纪要，列个表，顺便标出还没定的事」

不适用：替用户拍板决策、评价同事、编造未出现的信息、代发邮件/日程。

## 输入约定

- 输入是**自由文本**（会议记录、聊天记录、语音转写均可），可能带发言人或时间戳，也可能没有。
- 如果缺少会议主题/参会人，可以从正文推断并用「（推断）」标注；无法推断就写「未提供」。
- 输入可能夹杂寒暄、重复、跑题内容，需要过滤，但要保留与结论相关的原话依据。

## 处理步骤

### 第 1 步：读全文，标出四类信息

1. **决定**：已经拍板的事项（谁说、定了什么）。
2. **行动项**：需要有人去做的事（隐含动词：跟进、整理、确认、发出、修复…）。
3. **未定/待确认**：说了一半、没有结论、需要上级或他人确认的事。
4. **风险/依赖**：会卡住其他事项的前提条件。

### 第 2 步：把行动项拆成 5 个字段

| 字段 | 规则 |
|---|---|
| 事项 | 一句话，动词开头，可验收（「产出 X」而不是「关注 X」） |
| 负责人 | 原文明确提到才填；多人写「A、B」；**原文没有就写「待确认」，不得猜测** |
| 截止时间 | 原文有明确日期/相对时间（「下周三前」）就填，并注明「相对时间，需按会议日期换算」；没有就写「未定」 |
| 产出物 | 交付形态（文档/表格/代码/结论），原文没提写「未说明」 |
| 依赖/风险 | 依赖谁、卡在什么条件上；没有就留空 |

### 第 3 步：合并与去重

- 同一件事被多人重复提到 → 合并为一条，负责人取实际执行者。
- 一个行动项包含多个可独立验收的子任务 → 拆开。
- 纯讨论、纯表态、纯寒暄 → 不进行动项表。

### 第 4 步：标注不确定

- 所有「猜出来」的内容一律加「（推断）」，并在文末「需人工确认」区集中列出。
- **不得编造负责人、日期、数字、结论。** 原文没有的信息宁缺勿造。

## 输出格式（严格按此结构）

```markdown
# <会议主题或「未命名会议」> · 行动项清单

- 会议时间：<原文有则填，否则「未提供」>
- 参会人：<原文有则填，否则「未提供」>
- 整理依据：<原文长度/条数等一句话说明>

## 一、会议结论

1. <结论一>（依据：<原话片段>）
2. …

## 二、行动项

| # | 事项 | 负责人 | 截止 | 产出物 | 依赖/风险 |
|---|---|---|---|---|---|
| 1 | … | … | … | … | … |
| 2 | … | … | … | … | … |

## 三、未定事项 / 需人工确认

1. <事项>：卡在 <原因>，建议 <下一步>（推断，需确认）
2. …

## 四、风险与依赖

- <风险>：影响 <哪些行动项>（依据：<原话片段>）

## 五、一句话总结

<2 句话内说清：这次会定了什么、接下来最该盯哪件事>
```

## 硬性规则

1. **不编造**：负责人、截止时间、数字、结论都必须能在原文找到依据；找不到标「待确认」或「（推断）」。
2. **可验收**：行动项必须是动词开头、有明确产出，禁止「持续关注」「加强沟通」这类无法验收的表述。
3. **区分决定与待办**：决定进「结论」，待办进「行动项」，两者不混。
4. **保留依据**：结论与风险尽量附一句原话片段，便于回查。
5. **不评价人**：不做绩效评价、不推测动机、不点名批评。
6. **隐私**：输出中如含手机号、邮箱、身份证号等，改用「（已隐去）」。
7. **不夸大**：原文没说「紧急」就不要标紧急；原文没说「必须」就不要写成硬要求。
8. **长度可控**：行动项超过 15 条时，按负责人分组、只保留有明确产出的，其余归入「未定/需确认」。

## 输出前自检

- [ ] 行动项每条都能在原文找到依据？
- [ ] 负责人/截止期缺失的都写了「待确认」/「未定」，没有猜测？
- [ ] 决定和待办分开了？
- [ ] 每条行动项都能验收（有产出物）？
- [ ] 推断内容都标了「（推断）」并汇总到需确认区？
- [ ] 没有编造数字、没有人身评价、没有敏感信息外泄？
